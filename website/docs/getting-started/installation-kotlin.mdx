alphaTab for Kotlin runs on any JVM, for servers, command-line tools and headless rendering, and in Android apps with a native `AlphaTabView`.

## Install

Two packages on Maven Central cover the Kotlin target:

- [`net.alphatab:alphaTab-core`](https://central.sonatype.com/artifact/net.alphatab/alphaTab-core) runs on any JVM 17 or newer. It contains the importers and exporters, the renderer and the synthesizer, and is used through the [low-level APIs](/docs/guides/lowlevel-apis). It has no UI control and no audio output.
- [`net.alphatab:alphaTab`](https://central.sonatype.com/artifact/net.alphatab/alphaTab) is the Android library (minSdk 26). It adds the `AlphaTabView`, the Android canvas and the audio output, and brings in `alphaTab-core` as a dependency.

Always use both packages in the same version: `net.alphatab:alphaTab` requires exactly its own version of `alphaTab-core`. Pre-release snapshots are published to [central.sonatype.com/repository/maven-snapshots](https://central.sonatype.com/repository/maven-snapshots/).

## Render on the JVM {#render-on-the-jvm}

On a JVM, alphaTab renders through alphaSkia, which needs a native library per operating system: `net.alphatab:alphaSkia-windows`, `alphaSkia-linux` or `alphaSkia-macos`, with the entry points `AlphaSkiaWindows`, `AlphaSkiaLinux` and `AlphaSkiaMacOs`. Use alphaSkia `{{alphaSkiaVersion}}`, the version `alphaTab-core` depends on.

alphaSkia also needs the Bravura music font. It ships as `dist/font/Bravura.otf` in the [`@coderline/alphatab`](https://www.npmjs.com/package/@coderline/alphatab) npm package.

This command-line program loads a file, renders it 970 pixels wide and writes one PNG per rendered part:

```kotlin
import alphaTab.Environment
import alphaTab.Settings
import alphaTab.alphaSkia.AlphaSkiaLinux
import alphaTab.collections.DoubleList
import alphaTab.core.ecmaScript.Uint8Array
import alphaTab.importer.ScoreLoader
import alphaTab.platform.skia.AlphaSkiaImage
import alphaTab.rendering.ScoreRenderer
import java.io.File
import kotlin.contracts.ExperimentalContracts

@OptIn(ExperimentalUnsignedTypes::class, ExperimentalContracts::class)
fun main(args: Array<String>) {
    AlphaSkiaLinux.INSTANCE.initialize()
    Environment.enableAlphaSkia(File("Bravura.otf").readBytes().asUByteArray(), null)

    val score = ScoreLoader.loadScoreFromBytes(Uint8Array(File(args[0]).readBytes().asUByteArray()), null)

    val settings = Settings()
    settings.core.engine = "skia"
    settings.core.enableLazyLoading = false

    val renderer = ScoreRenderer(settings)
    renderer.width = 970.0

    var index = 0
    renderer.partialRenderFinished.on { result ->
        (result.renderResult as AlphaSkiaImage).use { image ->
            File("score-${index++}.png").writeBytes(image.toPng()!!.asByteArray())
        }
    }
    renderer.renderFinished.on { result ->
        println("Rendered $index images, ${result.totalWidth}x${result.totalHeight}")
    }

    renderer.renderScore(score, DoubleList(0.0), null)
}
```

- `enableLazyLoading = false` renders every part right away. With lazy loading, a part is only rendered once a UI requests it.
- Text uses the fonts installed on the system. On a server without fonts, register them with `Environment.registerAlphaSkiaCustomFont`.
- Set `settings.core.engine = "svg"` to receive every part as an SVG string instead. Initialize alphaSkia anyway: alphaTab measures text through it.

The [low-level API guide](/docs/guides/lowlevel-apis) shows MIDI generation, audio synthesis and JSON serialization with the same classes.

## Render on Android {#render-on-android}

Add the `AlphaTabView` control to any layout. This example places it inside a `ConstraintLayout` that fills the activity:

```xml
<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/main_view"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context="net.alphatab.android.MainActivity">

    <alphaTab.AlphaTabView
        android:id="@+id/alphatab_view"
        android:layout_width="match_parent"
        android:layout_height="match_parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintBottom_toBottomOf="parent" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

Get a reference to the view from your activity and use its `api` property to drive alphaTab:

```kotlin
import alphaTab.AlphaTabView

class MainActivity : ComponentActivity() {
    private lateinit var alphaTabView: AlphaTabView

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        alphaTabView = findViewById(R.id.alphatab_view)
        val api = alphaTabView.api
        // load a score, subscribe to events, drive playback here
    }
}
```

The Android library bundles the Bravura font and the default SoundFont and initializes alphaSkia itself. More samples live at [github.com/CoderLine/alphaTabSamplesAndroid](https://github.com/CoderLine/alphaTabSamplesAndroid/).

## Jetpack Compose

alphaTab does not currently ship a Compose control. Two options:

- Vote on the [roadmap issue](https://github.com/CoderLine/alphaTab/issues/1475) to signal demand.
- [Wrap the classic `AlphaTabView`](https://developer.android.com/develop/ui/compose/libraries) inside a Compose tree using `AndroidView`.

## Dependencies

alphaTab for Kotlin carries a small number of third-party dependencies:

- **Rendering.** [alphaSkia](https://github.com/CoderLine/alphaSkia), which wraps the Skia engine used by Chrome, or the SVG output. On Android the built-in Android `Canvas` is available as well; alphaSkia is significantly faster.
- **Async.** `org.jetbrains.kotlinx:kotlinx-coroutines-core` powers alphaTab's asynchronous operations.

There is no UI control for desktop JVM toolkits such as Swing or JavaFX. Reach out on GitHub if you need alphaTab wired to a different UI framework or audio backend.
