This page tells you which alphaTab setup fits your bundler or framework and what every setup has in common.

```bash
npm install @coderline/alphatab
```

With webpack, Rspack, Rsbuild or Vite, also install the plugin for your bundler and register it in its config:

```bash
npm install --save-dev @coderline/alphatab-webpack   # webpack, Rspack, Rsbuild
npm install --save-dev @coderline/alphatab-vite      # Vite
```

```js
// vite.config.js
import { defineConfig } from 'vite';
import { alphaTab } from '@coderline/alphatab-vite';

export default defineConfig({
    plugins: [alphaTab()]
});
```

Without a bundler, load alphaTab from a CDN as shown in [Installation (Web)](installation-web).

## Choose your setup {#choose}

Find your bundler or framework and follow its page. Every setup listed here was verified with a sample project in [alphaTabSamplesWeb](https://github.com/CoderLine/alphaTabSamplesWeb): the score renders in a Web Worker and plays through the Audio Worklet.

"Core copies" counts how many copies of alphaTab's core (about 1.2 MiB minified, 300 kB gzipped) the browser downloads. One is the target: the page, the Web Workers and the Audio Worklet then share a single file.

## How alphaTab loads its code {#bundle-structure}

alphaTab runs in three places: the page, a Web Worker for rendering and synthesis, and an Audio Worklet for the audio output. The package entry `alphaTab.mjs` imports the library from `alphaTab.core.mjs`. It starts the worker and the worklet from two small entry files, which import the same core:

<div className="text--center"><BundleStructure role="img" aria-labelledby="alphatab-bundle-structure-title" style={{ maxWidth: "100%", height: "auto" }} /></div>

alphaTab references the entry files in the standard form bundlers understand:

```js
new Worker(new URL('./alphaTab.worker.mjs', import.meta.url), { type: 'module' });
alphaTabWorklet.addModule(new URL('./alphaTab.worklet.mjs', import.meta.url));
```

Without a bundler, the browser loads these files as they are and fetches the core once. A bundler has to do three things to get the same result:

- turn the worker URL into a worker entry;
- turn the worklet URL into a worklet entry, which most bundlers do not support;
- put the core into one chunk that the page, the worker and the worklet all load.

The webpack and Vite plugins do all three. For other bundlers you own the worker and worklet entries yourself, through the `@coderline/alphatab/core`, `@coderline/alphatab/worker` and `@coderline/alphatab/worklet` exports; see [Installation (other bundlers)](installation-other-bundlers).

## What every setup needs {#requirements}

### Create alphaTab in the browser only {#client-only}

alphaTab needs the DOM, Web Workers and Web Audio. In frameworks with server-side rendering, create the `AlphaTabApi` in a hook that only runs in the browser: `useEffect` in React, `onMounted` in Vue, `afterNextRender` in Angular, `onMount` in Svelte and Solid. Destroy it with `api.destroy()` when the component unmounts. Importing `@coderline/alphatab` on the server is safe; only creating the API needs the browser.

### Point alphaTab to the font and the SoundFont {#assets}

alphaTab loads the Bravura music font and a SoundFont at runtime. The plugins copy both into your build output, as `font/` and `soundfont/` at its root. Set the two locations in the settings:

```js
import * as alphaTab from '@coderline/alphatab';

const element = document.getElementById('alphaTab');
const api = new alphaTab.AlphaTabApi(element, {
    core: {
        fontDirectory: '/font/'
    },
    player: {
        enablePlayer: true,
        soundFont: '/soundfont/sonivox.sf2'
    }
});
```

- [`player.soundFont`](/docs/reference/settings/player/soundfont) has no default. Set it whenever the player is enabled.
- [`core.fontDirectory`](/docs/reference/settings/core/fontdirectory) defaults to a `font/` folder next to the script that contains alphaTab's core. That matches the plugin's copy only when the bundler writes its scripts to the root of the output. Vite writes them to `assets/` and Rsbuild to `static/js/`, so set `fontDirectory` there. If nothing renders and the network panel shows failed font requests, this setting is the cause.
- Prefix both paths with the base path of your app if it is not served from `/`, for example `import.meta.env.BASE_URL` with Vite.

### Load every entry file {#entry-files}

With webpack and Rspack, alphaTab's core is a chunk of its own that the page loads next to your entry script. HTML generated by `HtmlWebpackPlugin`, `HtmlRspackPlugin`, Rsbuild or Next.js includes it. If you write the `<script>` tags yourself, include every file of the entrypoint, not only `main.js`.
