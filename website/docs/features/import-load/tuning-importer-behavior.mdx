Users hand you a GP5 file with Cyrillic or Japanese titles, a Guitar Pro 4 file that stashed the lyrics inside beat text, a piano MusicXML export that treats the right and left hand as two parts, or an oversized GP file with embedded audio. Each case has an importer setting that fixes it in one line.

## The knobs

### `importer.encoding` and `importer.gp3To5encoding`

Two encoding hints control string decoding. `importer.encoding` applies to Guitar Pro 6, Guitar Pro 7, and MusicXML; `importer.gp3To5encoding` applies to the older Guitar Pro 3-5 binary format, which stored strings in the system ANSI code page. Both default to `utf-8`. When titles, lyrics, or comments come back garbled, the source was written in a legacy code page — set the matching encoding (for example `windows-1252` for western European Guitar Pro files, `shift_jis` for Japanese) and reload. Supported encoding names depend on the runtime — browsers accept whatever `TextDecoder` supports; .NET uses `System.Text.Encoding`.

### `importer.mergePartGroupsInMusicXml`

MusicXML `part-group` elements bracket related parts (piano left and right hand, choir voices, brass section). Default: `false` — each `part` becomes its own alphaTab track. Set to `true` to fold every group into a single track with multiple staves. Use it when your source treats each staff of a grand-staff instrument as a separate part.

### `importer.beatTextAsLyrics`

Older Guitar Pro 3-5 files often stored lyrics in the per-beat text field because the dedicated lyrics feature was awkward to use. Default: `false`, which shows those texts as beat texts above the notation. Set to `true` and alphaTab parses those beat texts as lyrics, splitting on dashes, underscores, and spaces the way GP renders them. The heuristic is imperfect — enable it only for files that suffer from the old workflow, and only when the track has no proper lyrics attached.

### `importer.maxDecodingBufferSize`

Safety cap on intermediate buffers used during decompression and string decoding, expressed in bytes. Defaults to `128000000` (128 MB). Very large scores — especially GP files with embedded audio — may need a higher limit. Server-side callers should keep this snug to avoid resource exhaustion on hostile input. Available since 1.9.0.

## Show it in code

Set all five in one settings object:

```js
import * as alphaTab from '@coderline/alphatab';

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, {
  core: { file: '/scores/song.gp5' },
  importer: {
    encoding: 'windows-1252',        // GP6/7 + MusicXML
    gp3To5encoding: 'windows-1252',  // GP3-5 legacy code page
    mergePartGroupsInMusicXml: true, // MusicXML-only
    beatTextAsLyrics: true,          // GP3-5 lyrics-in-beat-text workaround
    maxDecodingBufferSize: 256_000_000,
  },
});
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of obtaining the render target — a `<div>` on Web, an `AlphaTab` control on .NET, or an `AlphaTabView` on Android. Every other line runs unchanged on all three runtimes.
