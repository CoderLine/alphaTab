## The four classes

alphaTab tags four overlay elements with stable classes. Target them from your stylesheet:

- `.at-cursor-bar` — the rectangle behind the currently played bar.
- `.at-cursor-beat` — the vertical line at the currently played beat. Give it an explicit `width` — without one it collapses to zero.
- `.at-highlight` — applied to the SVG groups of the currently played beat when the render engine is SVG. Style both `fill` and `stroke` to catch every shape.
- `.at-selection` — wrapper the range-selection overlay uses; a child `div` per bar area sits inside.

## Animating or ticking the beat cursor

The beat cursor can either slide smoothly across the beat's width or tick from beat to beat. `player.enableAnimatedBeatCursor` picks between the two. It defaults to `true`. Turn it off for editor UIs where a hard step is easier to read. The difference shows up during playback — press play in the demo above and toggle the checkbox to watch the beat cursor switch between a smooth slide and a hard step per beat.

## Show it in code

```css
/* Highlight overlays */
.at-cursor-bar {
  background: rgba(255, 242, 0, 0.25);
}

.at-cursor-beat {
  background: rgba(64, 64, 255, 0.75);
  width: 3px;
}

.at-highlight * {
  fill: #0078ff;
  stroke: #0078ff;
}

.at-selection div {
  background: rgba(64, 64, 255, 0.1);
}
```

```js
import * as alphaTab from '@coderline/alphatab';

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, {
  core: { file: '/scores/song.gp' },
  player: {
    playerMode: alphaTab.PlayerMode.EnabledAutomatic,
    enableAnimatedBeatCursor: true,
  },
});
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of
obtaining the render target. Every other line runs unchanged on all three
runtimes.
