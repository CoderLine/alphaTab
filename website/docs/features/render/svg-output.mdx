Render every glyph, staff line, and beam as SVG geometry. The result is a resolution-independent DOM tree you can zoom, style with CSS, hit-test, or hand to a printer without rasterization artifacts.

## When SVG is the right pick

SVG is the default backend on Web and the recommended output whenever the render target has to survive scaling or printing:

- **Scales without loss.** Zoom or export at any DPI; the glyph outlines stay crisp.
- **Prints cleanly.** Browsers rasterize SVG at printer resolution, so bar lines and note heads land pixel-accurate on paper.
- **Accessible and searchable.** Each rendered element sits in the DOM with class names, so screen readers, custom overlays, and DOM queries all work.
- **Available on every platform.** SVG runs the same on Web, .NET, and Android — pass `engine: 'svg'` anywhere and get identical output.

The trade-off is throughput. On very dense scores (hundreds of bars in a single view) the DOM grows large and layout thrash can appear during scroll. For that case, reach for [HTML5 Canvas](html5-canvas) on Web or [Skia](skia-backend) on .NET / Android.

## Show it in code

```js
import * as alphaTab from '@coderline/alphatab';

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, {
  core: {
    file: '/scores/canon.gp',
    engine: 'svg',
  },
});
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of obtaining the render target — a `<div>` on Web, an `AlphaTab` control on .NET, or an `AlphaTabView` on Android. Every other line runs unchanged on all three runtimes.
