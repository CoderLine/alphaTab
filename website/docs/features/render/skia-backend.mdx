On .NET and Android, alphaTab renders through [alphaSkia](https://github.com/CoderLine/alphaSkia) — a thin wrapper around Google's [Skia](https://skia.org/) library. The result is high-quality raster output with identical glyph metrics across Windows, macOS, Linux, and Android.

The live demo above uses SVG because Skia is not available in the browser — it targets native runtimes only. The code snippet below configures Skia on .NET or Android.

## What Skia gets you

- **Native raster on every non-web target.** Skia is the default engine on .NET and Android, so leaving `engine` unset already picks it. Setting it explicitly makes intent clear.
- **Consistent output across platforms.** The same score renders identically on WPF, MAUI, and Android — no more platform-specific font hinting differences.
- **PNG export.** The alphaSkia canvas exposes `toPng()`, which is what powers the [Node.js headless rendering](nodejs-headless-rendering) workflow.
- **Custom font support.** Register `.ttf` / `.otf` files with `Environment.registerAlphaSkiaCustomFont` and use them in `display.resources`. See [Custom fonts on Skia](/docs/features/extend/skia-fonts).

Skia is not available on the Web runtime. If you request `engine: 'skia'` from a browser context, alphaTab falls back to the platform default (SVG).

## Show it in code

```js
import * as alphaTab from '@coderline/alphatab';

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, {
  core: {
    file: '/scores/song.gp',
    engine: 'skia',
  },
});
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of obtaining the render target — an `AlphaTab` control on .NET or an `AlphaTabView` on Android. On desktop .NET you typically embed the WPF or WinForms control; on Android you place `AlphaTabView` in a layout.

For a Node.js pipeline that renders to PNG on the server, see [Node.js headless rendering](nodejs-headless-rendering).
