Every level of the score model — score, track, staff, bar, voice, beat, note — carries a `style` container. Assign a color to any sub-element and the render reflects it. Use it to highlight a wrong note in a tutor app, tint a specific voice, or theme the whole document.

## Where the elements live

Each level exposes its own `SubElement` enum of individually colorable parts:

- `ScoreSubElement` — title, subtitle, artist, album, copyright, tempo mark.
- `TrackSubElement` — track name, accolade bracket, string tuning.
- `BarSubElement` — barlines, bar numbers, key and time signature glyphs.
- `VoiceSubElement` — beam, tuplet bracket.
- `BeatSubElement` — stem, flag, chord name, beat text.
- `NoteSubElement` — note head, accidental, tab fret text, fingering, effect glyph.

The full enumeration for each level lives in the [model reference](/docs/reference/score).

## Show it in code

Coloring is applied post-load, so wire it in a `scoreLoaded` handler:

```js
import * as alphaTab from '@coderline/alphatab';

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, {
  core: { file: '/scores/song.gp' },
});

api.scoreLoaded.on((score) => {
  score.style = new alphaTab.model.ScoreStyle();
  score.style.colors.set(
    alphaTab.model.ScoreSubElement.Title,
    alphaTab.model.Color.fromJson('#426d9d')
  );

  for (const track of score.tracks) {
    track.style = new alphaTab.model.TrackStyle();
    track.style.colors.set(
      alphaTab.model.TrackSubElement.StringTuning,
      alphaTab.model.Color.fromJson('#e04c4c')
    );
  }
});
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of obtaining the render target — a `<div>` on Web, an `AlphaTab` control on .NET, or an `AlphaTabView` on Android. Every other line runs unchanged on all three runtimes.
