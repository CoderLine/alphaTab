## Two pieces per font

A SMuFL font has two halves and alphaTab needs both:

- **The font file itself** — an `.otf`, `.woff`, or `.woff2` containing the glyphs. Point alphaTab at it via `core.smuflFontSources`, a `Map<FontFileFormat, string>` of URLs.
- **The `metadata.json` sidecar** — engraving metrics that tell alphaTab how each glyph should be sized and spaced. Load the JSON yourself and hand it to `display.resources.engravingSettings.fillFromSmufl()`.

Miss either half and the score renders with the wrong spacing, the wrong glyphs, or both. When `fillFromSmufl` finds glyphs the source file does not declare, it logs warnings — watch the console when you first wire up a new font.

## Show it in code

```js
import * as alphaTab from '@coderline/alphatab';

const settings = new alphaTab.Settings();
settings.core.smuflFontSources = new Map([
  [alphaTab.FontFileFormat.OpenType, '/fonts/Petaluma.otf'],
]);

const metadata = await fetch('/fonts/petaluma_metadata.json').then(r => r.json());
settings.display.resources.engravingSettings.fillFromSmufl(metadata);

const container = getAlphaTabContainer();
const api = new alphaTab.AlphaTabApi(container, settings);
```

`getAlphaTabContainer()` is a placeholder for the platform-specific step of obtaining the render target — a `<div>` on Web, an `AlphaTab` control on .NET, or an `AlphaTabView` on Android. Every other line runs unchanged on all three runtimes.

## Limitations

- **No live font swap.** Reassigning `smuflFontSources` on a running instance does not re-render with the new font. Destroy the `AlphaTabApi` and create a fresh one to switch fonts at runtime.
- **Incomplete fonts.** Few SMuFL fonts cover the full glyph range alphaTab uses. alphaTab has no per-glyph fallback — missing glyphs render as gaps or as the font's own placeholder. Bravura, Petaluma, and Leland are the safest choices.
