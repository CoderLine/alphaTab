## 1.9.0

This release reworks note spacing and the placement of annotations, adds per-staff control over clefs, key and time signatures and bar numbers, plays repeats and jumps in the right order, and imports MusicXML files more faithfully. The [upgrade notes](#upgrade-notes) at the end list the visual changes, changed defaults and deprecations.

### Music Notation

#### render: power-law note spacing and last-system justification
https://github.com/CoderLine/alphaTab/pull/2749

alphaTab spaces notes with a power-law model, the approach Dorico, MuseScore and Finale use: doubling a duration multiplies its width by [`display.spacingRatio`](/docs/reference/settings/display/spacingratio). The default is `Math.SQRT2` (about 1.414, as in Dorico); values are clamped to 1.2–2.0. Whole notes and rest bars no longer take a large share of a system. [`display.stretchForce`](/docs/reference/settings/display/stretchforce) still sets the overall density.

The same four bars with `spacingRatio` 1.2 (first) and the default (second):

<AlphaTab tex={true} settings={{ display: { spacingRatio: 1.2 } }}>{`
\\hideDynamics
:1 C4 | :2 C4 C4 | :4 C4 C4 C4 C4 | :8 C4 C4 C4 C4 C4 C4 C4 C4
`}</AlphaTab>

<AlphaTab tex={true}>{`
\\hideDynamics
:1 C4 | :2 C4 C4 | :4 C4 C4 C4 C4 | :8 C4 C4 C4 C4 C4 C4 C4 C4
`}</AlphaTab>

[`display.lastSystemFillThreshold`](/docs/reference/settings/display/lastsystemfillthreshold) decides when the last system stretches to the full width: once its natural width reaches the given fraction of the available width. `1` (default) never stretches it, `0` always does, and values between `0.4` and `0.7` behave like Dorico and MuseScore. It replaces [`display.justifyLastSystem`](/docs/reference/settings/display/justifylastsystem).

Full demo and all options: [Density and spacing](/docs/features/render/density-and-spacing).

Thanks to [@AvaTheArchitect](https://github.com/AvaTheArchitect) for the discussion that led to this.

#### render: effect placement against the notation
https://github.com/CoderLine/alphaTab/pull/2750

Texts, chord names, dynamics, palm-mute and let-ring brackets and the other annotations are placed against the outline of the notation (the skyline) instead of in rows spanning the whole system. An annotation moves away from the staff only where a note, stem, beam or another annotation is in the way. Charts with many annotations need less vertical space.

<AlphaTexSample player={true}>{`
\\track "Guitar"
\\staff {score tabs}
:8 (0.5 2.4){ch "Am" dy mf} 2.3{lr} 1.2{lr} 0.1{lr} 1.2 2.3{txt "rit."} :4 2.4 |
:8 0.6{pm} 0.6{pm} 3.6{pm} 0.6{pm} :16 12.1{txt "solo" h} 15.1{h} 12.1 14.2 :8 17.1{v} 12.1
`}</AlphaTexSample>

`Am` and `rit.` sit right above the low notes of the first bar, while the high sixteenth notes in the second bar push the labels and `solo` up. The placement is always active. [`display.effectBandPaddingBottom`](/docs/reference/settings/display/effectbandpaddingbottom) sets the gap between an annotation row and the staff or the row below it.

Full demo and all options: [Effect placement](/docs/features/render/effect-placement#skyline).

#### notation: per-staff display of clefs, key and time signatures, bar numbers and tab rests
https://github.com/CoderLine/alphaTab/pull/2752
https://github.com/CoderLine/alphaTab/pull/2946

Each staff type (standard notation, tablature, slash and numbered notation) has its own configuration for the elements it can draw: clef, key signature, time signature, bar numbers and, on tablature, rests. Each element can be hidden, drawn only on the topmost staff type of a staff, or drawn only in the first system. You set this score-wide on the stylesheet ([`RenderStylesheet.scoreConfig`](/docs/reference/types/model/renderstylesheet/#scoreconfig) and its siblings), per staff ([`Staff.scoreConfig`](/docs/reference/types/model/staff/#scoreconfig)) or per bar ([`Bar.scoreDisplay`](/docs/reference/types/model/bar/#scoredisplay)). The values are [`ElementDisplay`](/docs/reference/types/model/elementdisplay) records.

<AlphaTexSample player={true}>{`
\\staff {score tabs}
\\staffDisplay tabs { clefVisibility false tsPlacement allStaves restsPlacement allStaves }
:4 3.3 r 0.2 1.2 | 3.2 1.2 r 0.2
`}</AlphaTexSample>

The tab staff drops its TAB clef and repeats the time signature and the rests, which alphaTab otherwise draws only on the standard notation staff above it. The defaults render as before, apart from bar numbers (see the next item).

Full demo and all options: [Staff element display](/docs/features/render/staff-element-display#score-staff-and-bar-level).

#### notation: bar numbering with pick-up bars, custom numbers and texts
https://github.com/CoderLine/alphaTab/pull/2907

Bar numbers belong to the master bar. Pick-up bars get no number and do not count. [`MasterBar.customBarNumber`](/docs/reference/types/model/masterbar/#custombarnumber) restarts the count, and [`MasterBar.customBarNumberText`](/docs/reference/types/model/masterbar/#custombarnumbertext) shows a text such as `1a` instead of the number. In alphaTex, [`\barNumber`](/docs/alphatex/bar-metadata#barnumber) sets either one.

<AlphaTexSample player={true}>{`
\\defaultBarNumberDisplay allBars
\\ac :4 G4 |
:2 C5 E5 |
\\barNumber "1a" :2 D5 F5 |
\\barNumber 5 :1 C5
`}</AlphaTexSample>

The pick-up bar has no number, the third bar shows `1a`, and the last bar restarts the count at 5. By default, alphaTab now numbers only the first bar of each system. The number is centered above the start barline and no longer adds space at the start of the bar. Clef, key signature and time signature line up across the staves of a system. The MusicXML importer reads the `number` attribute of each measure.

Full demo and all options: [Bar numbers](/docs/features/render/bar-numbers#display-modes).

#### notation: tuning on the staff lines
https://github.com/CoderLine/alphaTab/pull/2742

alphaTab can write the note name of each open string at the left end of its tab line on the first system, instead of the tuning block above the score. This matches the "tuning before staff" option in Guitar Pro. Select it with [`RenderStylesheet.tuningDisplayMode`](/docs/reference/types/model/renderstylesheet/#tuningdisplaymode) set to `TuningDisplayMode.Staff`, or with [`\tuningDisplayMode staff`](/docs/alphatex/score-metadata#tuningdisplaymode) in alphaTex. [`display.inlineTuningPaddingRight`](/docs/reference/settings/display/inlinetuningpaddingright) sets the gap between the labels and the staff.

<AlphaTexSample player={true}>{`
\\tuningDisplayMode staff
\\track "Guitar"
\\staff { tabs }
\\tuning (E4 B3 G3 D3 A2 D2)
:8 0.6 2.4 0.3 2.2 0.1 2.2 0.3 2.4
`}</AlphaTexSample>

Guitar Pro 7 and 8 files store the mode in their stylesheet; alphaTab reads it and the Guitar Pro 7 exporter writes it.

Full demo and all options: [Tuning display](/docs/features/render/tuning-display#tuning-on-staff).

Thanks to [@kulek1](https://github.com/kulek1) for contributing this feature, and to [@AvaTheArchitect](https://github.com/AvaTheArchitect) for the discussion that led to it.

#### notation: drum tablature
https://github.com/CoderLine/alphaTab/pull/2591

Percussion staves can render as a drum tablature, as in Guitar Pro and TuxGuitar. Each drum piece sits on a line, and the number on the line is its articulation number. Turn it on with [`Staff.showTablature`](/docs/reference/types/model/staff/#showtablature), or with `\staff { score tabs }` in alphaTex. In alphaTex, `@` assigns the line of a percussion note: `SnareHit@3` places the snare on line 3.

<AlphaTexSample player={true}>{`
\\track "Drums" { instrument percussion }
\\staff { score tabs }
\\clef neutral
\\articulation defaults
:4 (KickHit@5 HiHatClosed@1) (SnareHit@3 HiHatClosed@1) (KickHit@5 HiHatClosed@1) (SnareHit@3 HiHatClosed@1)
`}</AlphaTexSample>

Guitar Pro 7 and 8 files keep the line of every drum note on import and export.

Full demo and all options: [Drum and percussion notation](/docs/features/render/drum-tabs#drum-tablature).

Thanks to [@leocaseiro](https://github.com/leocaseiro) for contributing this feature, and to [@sugizo](https://github.com/sugizo) for the discussion that led to it.

#### notation: hammer-on, pull-off and slide labels above the staff
https://github.com/CoderLine/alphaTab/pull/2945
https://github.com/CoderLine/alphaTab/pull/2943

The `H`, `P` and `sl.` labels introduced in 1.8.3 are drawn above the staff instead of on the slur arcs, on standard notation, tablature and numbered notation. Each beat gets one label, centered on its slur segment; different labels on one beat stack. A segment across a system break is labeled on the first system only. Regular slurs carry no label.

Slurs between chords follow Behind Bars and Guitar Pro: on standard notation one slur joins the outer noteheads of the chord, on tablature each beat gets at most one arc above and one below. On narrow screens these slurs no longer disappear.

<AlphaTexSample player={true}>{`
\\staff {score tabs}
:4 r r 5.3{h} 7.3{h} | 5.3 r r (5.1{h} 5.2{sl}) | (7.1 9.2) r r r
`}</AlphaTexSample>

Hide the labels with [`NotationElement.EffectHammerOnPullOffText`](/docs/reference/types/notationelement#effecthammeronpullofftext) and [`NotationElement.EffectSlideText`](/docs/reference/types/notationelement#effectslidetext) in [`notation.elements`](/docs/reference/settings/notation/elements).

Full demo and all options: [Effects and articulations](/docs/features/render/coverage-effects-articulations#slide-labels).

Thanks to [@shimabox](https://github.com/shimabox) for reporting the problem with slurs between chords.

#### notation: centered full-bar notes and rests
https://github.com/CoderLine/alphaTab/pull/2781

When a bar holds a single beat that lasts the whole bar, alphaTab centers it in the bar together with its annotations, following Behind Bars. This applies when every staff and voice rendered in the bar has one such beat; other bars keep the regular positioning.

<AlphaTexSample player={true}>{`
\\hideDynamics
:1 C5 | r.1 | \\ts (3 4) :2 C5{d} | r.2{d}
`}</AlphaTexSample>

Full demo and all options: [Rests and full-bar notes](/docs/features/render/coverage-rests#centered).

Thanks to [@comus111](https://github.com/comus111) for the discussion that led to this.

#### notation: rest position per beat
https://github.com/CoderLine/alphaTab/pull/2721

A rest can take the staff position of a given pitch instead of the automatic one. In alphaTex, write the beat property [`restDisplayPitch`](/docs/alphatex/beat-properties#restdisplaypitch); in the model, set [`Beat.restDisplayTone`](/docs/reference/types/model/beat/#restdisplaytone) and [`Beat.restDisplayOctave`](/docs/reference/types/model/beat/#restdisplayoctave). The position follows the clef and works per voice.

<AlphaTexSample player={true}>{`
\\hideDynamics
:4 r C5 r C5 | r{restDisplayPitch A5} C5 r{restDisplayPitch E4} C5
`}</AlphaTexSample>

The first bar shows the automatic positions, the second bar moves the rests to A5 and E4. alphaTab does not read rest positions from Guitar Pro or MusicXML files, and the alphaTex exporter does not write `restDisplayPitch`.

Full demo and all options: [Rests and full-bar notes](/docs/features/render/coverage-rests#rest-position).

Thanks to [@roscopeeco](https://github.com/roscopeeco) for contributing this feature.

### Player

#### player: repeats, alternate endings and jumps play in the right order
https://github.com/CoderLine/alphaTab/pull/2915
https://github.com/CoderLine/alphaTab/pull/2895
https://github.com/CoderLine/alphaTab/pull/2917
https://github.com/CoderLine/alphaTab/pull/2929

The player, the cursor and MIDI export follow one set of rules for repeats and jumps:

* Each D.C. and D.S. is taken once. Before, a coda placed before the bar that jumps back could make playback loop forever.
* After a jump, repeats play as their final pass: the passage plays once, with only its last alternate ending, as in MuseScore.
* Repeat passes are counted per repeat group, so a repeat sign in several alternate endings plays every ending once, as in Guitar Pro 8.
* A jump inside a repeat, or on its closing bar, is taken after all repeat passes.
* A jump on an alternate ending that playback skips is not taken.
* MusicXML files that write jumps and markers as `<sound>` attributes inside a `<direction>`, as MuseScore exports them, play these jumps.

<AlphaTexSample player={true}>{`
\\track "Guitar"
\\staff {score}
\\ro :4 C4 D4 E4 F4 |
\\ae 1 \\rc 2 G4 F4 E4 D4 |
\\ae 2 \\jump fine G4 E4 :2 C4 |
\\jump daCapoAlFine :4 A4 G4 F4 E4
`}</AlphaTexSample>

This plays bars 1 2 1 3 4 1 3: after the D.C. the repeat plays as its final pass, so bar 1 continues into the second ending, where `Fine` ends the piece.

Full demo and all options: [Repeats and structural elements](/docs/features/render/coverage-repeats#playback-order).

Thanks to [@AnshulJ999](https://github.com/AnshulJ999) and [@gabbe](https://github.com/gabbe) for reporting these problems, and to [@noy-solvin](https://github.com/noy-solvin) for contributing the fix for repeats in alternate endings.

#### player: pick-up bars for metronome, count-in and beaming
https://github.com/CoderLine/alphaTab/pull/2939

alphaTab treats a pick-up bar as the end of a full bar. Beaming, triplet feel and metronome clicks follow the beats of the time signature. The count-in counts one full bar and continues up to the beat where playback starts, also when you start in the middle of a bar.

<AlphaTexSample player={true}>{`
\\ts (2 4)
\\ac C4.8 D4.8 E4.8 |
F4.4 G4.4 |
A4.8 B4.8 C5.8 D5.8
`}</AlphaTexSample>

The pick-up holds the last three eighths of a 2/4 bar: C keeps its own flag, and D and E are beamed as beat 2. The same change corrects beat timers with several tracks and tempo changes within a bar, and reading [`MidiFile.events`](/docs/reference/types/midi/midifile) with `MidiFileFormat.MultiTrack` no longer overflows the stack.

Full demo and all options: [Count-in and metronome](/docs/features/play-sync/count-in-and-metronome#pick-up-bars).

Thanks to [@AlbinoBJJ](https://github.com/AlbinoBJJ) for reporting this problem.

#### integration: separate settings for seek, range selection and click reset
https://github.com/CoderLine/alphaTab/pull/2779

Three settings replace [`player.enableUserInteraction`](/docs/reference/settings/player/enableuserinteraction):

* [`player.enableSeekToClick`](/docs/reference/settings/player/enableseektoclick) moves the playhead to the clicked beat.
* [`player.enablePlaybackRangeSelection`](/docs/reference/settings/player/enableplaybackrangeselection) selects a playback range by dragging.
* [`player.resetPlaybackRangeOnClick`](/docs/reference/settings/player/resetplaybackrangeonclick) clears the range on a plain click. With `false`, a click keeps the range and seeks within it.

All three default to `true`. A drag creates a range only once it reaches another beat; a press and release on the same beat counts as a click, even if the mouse moved a little.

```js
import * as alphaTab from '@coderline/alphatab';

const api = new alphaTab.AlphaTabApi(document.getElementById('alphaTab'), {
  core: { file: '/scores/song.gp' },
  player: {
    playerMode: alphaTab.PlayerMode.EnabledAutomatic,
    enableSeekToClick: true,
    enablePlaybackRangeSelection: true,
    resetPlaybackRangeOnClick: false,
  },
});
```

Full demo and all options: [Enabling and disabling interaction](/docs/features/interact/enabling-and-disabling-interaction#keep-the-range-on-click).

Thanks to [@AvaTheArchitect](https://github.com/AvaTheArchitect) for the discussion that led to this.

### alphaTex Extensions

#### alphaTex: staff display tags
https://github.com/CoderLine/alphaTab/pull/2946

Three tags express the staff element display settings: [`\defaultStaffDisplay`](/docs/alphatex/score-metadata#defaultstaffdisplay) for the whole score, [`\staffDisplay`](/docs/alphatex/staff-metadata#staffdisplay) for the current staff and [`\barDisplay`](/docs/alphatex/bar-metadata#bardisplay) for the current bar. Each takes optional staff types (`score`, `tabs`, `slash`, `numbered`, several in parentheses) and a property list such as `clefVisibility`, `tsPlacement` or `barNumber`. The alphaTex exporter writes these settings, so they survive a round trip.

<AlphaTexSample player={true}>{`
\\staff {score tabs}
:4 3.3 r 0.2 1.2 |
\\barDisplay tabs { tsPlacement allStaves } \\ts (3 4) 3.3 0.2 r | 1.2 r 0.2
`}</AlphaTexSample>

Only the change to 3/4 is restated on the tab staff.

Full demo and all options: [Staff element display](/docs/features/render/staff-element-display#alphatex).

### MusicXML Extensions

#### musicxml: note spelling from step and alter
https://github.com/CoderLine/alphaTab/pull/2931

Notes without a printed `<accidental>`, for example a repeated note in a bar or a note tied over the barline, were spelled from the key signature. An F♯ in F major became a G♭, a B in G♭ major became a C♭, and ties joined noteheads on different staff positions. alphaTab now spells every note from `<step>` and `<alter>`, as MuseScore and Verovio do.

<AlphaTab file="/files/releases/1.9/accidental-spelling.xml" />

In bar 1 the second F♯ stays on the F line, bars 2 and 3 tie the same notehead, and in bar 4 the B in G♭ major stays a B♮. The same change fixes the spellings the Guitar Pro exporter writes.

Thanks to [@gabbe](https://github.com/gabbe) for reporting this problem.

#### musicxml: more faithful import

Full list of supported elements: [MusicXML feature table](/docs/formats/musicxml#feature-table).

* musicxml: let ring, palm mute, wedges, octave shifts, slash notation and endings are paired per part, staff and number, so they end where the file says, and let ring and palm mute are audible ([#2938](https://github.com/CoderLine/alphaTab/pull/2938), thanks [@ppisljar](https://github.com/ppisljar))
* musicxml: `<string>` on a staff without tuning, as in classical guitar parts, becomes a string number on the pitched note instead of silencing the whole score ([#2913](https://github.com/CoderLine/alphaTab/pull/2913), thanks [@magmasystems](https://github.com/magmasystems))
* musicxml: `x` noteheads and `<play><mute>` become dead notes on fretted parts, and ties on transposed staves are kept ([#2914](https://github.com/CoderLine/alphaTab/pull/2914), thanks [@ppisljar](https://github.com/ppisljar))
* musicxml: `<fingering>` uses left-hand numbering on instruments other than piano, so a 1 is the index finger instead of the thumb ([#2927](https://github.com/CoderLine/alphaTab/pull/2927), thanks [@magmasystems](https://github.com/magmasystems))
* musicxml: D.C., D.S., To Coda, Coda, Segno and Fine written as `<sound>` attributes inside a `<direction>` are played as jumps ([#2929](https://github.com/CoderLine/alphaTab/pull/2929), thanks [@gabbe](https://github.com/gabbe))
* musicxml: `<metronome>` with a beat unit other than a quarter, or with dots, gives the right tempo, and a `<sound tempo>` in the same direction takes precedence ([#2910](https://github.com/CoderLine/alphaTab/pull/2910), thanks [@magmasystems](https://github.com/magmasystems))
* musicxml: harmonics written as base, touching and sounding notes, as Guitar Pro 8 exports them, become one harmonic note; in alphaTex, artificial and other harmonics on pitched notes such as `C4{ah 12}` sound and render ([#2947](https://github.com/CoderLine/alphaTab/pull/2947), thanks [@parvanitis15](https://github.com/parvanitis15))
* musicxml: notes with an `<instrument>` reference are treated as percussion only when that instrument is unpitched or the staff is a percussion staff ([#2777](https://github.com/CoderLine/alphaTab/pull/2777), thanks [@ldupoueyUB](https://github.com/ldupoueyUB))
* musicxml: high voice numbers are packed into consecutive voices per staff ([#2831](https://github.com/CoderLine/alphaTab/pull/2831))
* musicxml: the `number` attribute of each measure sets custom bar numbers and texts, and implicit measures become pick-up bars ([#2907](https://github.com/CoderLine/alphaTab/pull/2907); see [Bar numbers](/docs/features/render/bar-numbers#file-import))

### Guitar Pro Extensions

#### exporter: files Guitar Pro opens correctly
https://github.com/CoderLine/alphaTab/pull/2774
https://github.com/CoderLine/alphaTab/pull/2832
https://github.com/CoderLine/alphaTab/pull/2831
https://github.com/CoderLine/alphaTab/pull/2931

Files written by the [Guitar Pro 7 exporter](/docs/reference/types/exporter/gp7exporter) open correctly in Guitar Pro 7 and 8:

* The system layout is written in the form Guitar Pro expects. Before, the multi-track view of Guitar Pro 8 broke and its memory use grew without bound.
* Every note gets a string and fret, also on staves without a tuning such as piano parts or MusicXML imports.
* Voices beyond the four Guitar Pro supports move into free slots or are dropped with a warning, instead of crashing Guitar Pro.
* Notes keep their spelling in every key, for example a B♭ in F major.
* The exporter works on a copy of the score and leaves `api.score` unchanged.

Full demo and all options: [Export to Guitar Pro 7](/docs/features/export/export-to-guitar-pro-7#what-the-exporter-emits).

Thanks to [@chenkigba](https://github.com/chenkigba) for contributing the system layout fix.

#### importer: windows-1252 decoding for Guitar Pro 3–5
https://github.com/CoderLine/alphaTab/pull/2774

Guitar Pro 3–5 files store texts in the code page of the author's system. alphaTab decodes them with the new setting [`importer.gp3To5encoding`](/docs/reference/settings/importer/gp3to5encoding), `windows-1252` by default, so umlauts and other accented characters in titles and lyrics load correctly. A value other than `utf-8` in [`importer.encoding`](/docs/reference/settings/importer/encoding) still takes precedence.

Full demo and all options: [Tuning importer behavior](/docs/features/import-load/tuning-importer-behavior#importerencoding-and-importergp3to5encoding).

Thanks to [@chenkigba](https://github.com/chenkigba) for contributing this change.

### Upgrade Notes

#### Visual changes

* Horizontal spacing changes in every score with the power-law model ([#2749](https://github.com/CoderLine/alphaTab/pull/2749)). Adjust it with [`display.spacingRatio`](/docs/reference/settings/display/spacingratio) and [`display.stretchForce`](/docs/reference/settings/display/stretchforce); see [Density and spacing](/docs/features/render/density-and-spacing).
* Annotations sit closer to the notes ([#2750](https://github.com/CoderLine/alphaTab/pull/2750)). The default of [`display.effectBandPaddingBottom`](/docs/reference/settings/display/effectbandpaddingbottom) changes from `2` to `5`; raise or lower it to change the gap. See [Effect placement](/docs/features/render/effect-placement#band-padding).
* The default of [`display.staffPaddingLeft`](/docs/reference/settings/display/staffpaddingleft) changes from `2` to `6` ([#2907](https://github.com/CoderLine/alphaTab/pull/2907)). Set it to `2` for the previous padding.
* Notes and rests that fill a whole bar are centered ([#2781](https://github.com/CoderLine/alphaTab/pull/2781)), and hammer-on, pull-off and slide labels sit above the staff ([#2945](https://github.com/CoderLine/alphaTab/pull/2945)). Hide the labels through [`notation.elements`](/docs/reference/settings/notation/elements); see [Effects and articulations](/docs/features/render/coverage-effects-articulations#slide-labels).

#### Changed defaults

* Bar numbers appear on the first bar of each system instead of on every bar ([#2907](https://github.com/CoderLine/alphaTab/pull/2907)). Restore numbers on every bar with [`\defaultBarNumberDisplay allBars`](/docs/alphatex/score-metadata#defaultbarnumberdisplay) in alphaTex, or set `barNumber` to `BarNumberDisplay.AllBars` on the four staff configurations of the stylesheet. See [Bar numbers](/docs/features/render/bar-numbers#display-modes).
* Guitar Pro 3–5 files are decoded with [`importer.gp3To5encoding`](/docs/reference/settings/importer/gp3to5encoding), `windows-1252` by default, instead of UTF-8 ([#2774](https://github.com/CoderLine/alphaTab/pull/2774)). Set it to `utf-8` for the previous decoding. A value other than `utf-8` in `importer.encoding` still takes precedence. See [Tuning importer behavior](/docs/features/import-load/tuning-importer-behavior#importerencoding-and-importergp3to5encoding).
* A drag creates a playback range only once it reaches another beat, and a click that seeks while a range stays active is clamped to the range ([#2779](https://github.com/CoderLine/alphaTab/pull/2779)). See [Enabling and disabling interaction](/docs/features/interact/enabling-and-disabling-interaction#keep-the-range-on-click).

#### Deprecations

The deprecated members still work.

* [`player.enableUserInteraction`](/docs/reference/settings/player/enableuserinteraction): use [`player.enableSeekToClick`](/docs/reference/settings/player/enableseektoclick), [`player.enablePlaybackRangeSelection`](/docs/reference/settings/player/enableplaybackrangeselection) and [`player.resetPlaybackRangeOnClick`](/docs/reference/settings/player/resetplaybackrangeonclick). Setting it writes all three ([#2779](https://github.com/CoderLine/alphaTab/pull/2779)). See [Migrating from `enableUserInteraction`](/docs/features/interact/enabling-and-disabling-interaction#migrating-from-enableuserinteraction).
* [`display.justifyLastSystem`](/docs/reference/settings/display/justifylastsystem): use [`display.lastSystemFillThreshold`](/docs/reference/settings/display/lastsystemfillthreshold). `true` maps to `0`, `false` to `1` ([#2749](https://github.com/CoderLine/alphaTab/pull/2749)).
* [`RenderStylesheet.barNumberDisplay`](/docs/reference/types/model/renderstylesheet/#barnumberdisplay) and [`Bar.barNumberDisplay`](/docs/reference/types/model/bar/#barnumberdisplay): use the `barNumber` field of the staff configurations and bar overrides. Setting the old fields writes all four staff types ([#2752](https://github.com/CoderLine/alphaTab/pull/2752)). See [Deprecated bar number fields](/docs/features/render/staff-element-display#deprecated-bar-number-fields).

#### For integrations

* Unset values of [`Note.fret`](/docs/reference/types/model/note/#fret), [`Note.string`](/docs/reference/types/model/note/#string), [`Note.octave`](/docs/reference/types/model/note/#octave), [`Note.tone`](/docs/reference/types/model/note/#tone) and [`Note.percussionArticulation`](/docs/reference/types/model/note/#percussionarticulation) are `NaN` instead of `-1` ([#2591](https://github.com/CoderLine/alphaTab/pull/2591)). Replace `=== -1` checks with [`note.isStringed`](/docs/reference/types/model/note/#isstringed), [`note.isPercussion`](/docs/reference/types/model/note/#ispercussion), [`note.isPiano`](/docs/reference/types/model/note/#ispiano) or `Number.isNaN(...)`. A percussion note in a drum tablature is both percussion and stringed.
* Custom [`IMidiFileHandler`](/docs/reference/types/midi/imidifilehandler) implementations need the new member [`addMetronome(tick, counter, durationInTicks)`](/docs/reference/types/midi/imidifilehandler/#addmetronome); handlers that write standard MIDI files can ignore the call. In pick-up bars, [`Automation.ratioPosition`](/docs/reference/types/model/automation/#ratioposition) is relative to the full bar of the time signature, as Guitar Pro writes it ([#2939](https://github.com/CoderLine/alphaTab/pull/2939)).
* alphaTex AST consumers: the values of [`AlphaTexNodeType`](/docs/reference/types/importer/alphatex/alphatexnodetype) are renumbered, so compare against the enum members instead of numbers, and `AlphaTexNoteNode.noteStringDot` is now [`noteStringSeparator`](/docs/reference/types/importer/alphatex/alphatexnotenode/#notestringseparator) of type `IAlphaTexStringSeparatorNode` ([#2591](https://github.com/CoderLine/alphaTab/pull/2591)).
